# Phase 3.9 retro: Decision Debt

**Shipped:** 2026-09-06

## What shipped

The second of the three candidates evaluated alongside Incident
Correlation (see 3.8's retro) — explicitly built in full rather than the
cheaper discussion-volume-only proxy considered as an alternative when
these three ideas were first scoped. Flags pull requests with real
correlated Slack/Jira discussion but no correlated decision doc, and
whether the PR's author still shows any recent commit activity at all.

Required genuinely new capability, not just a new query over existing
data: GitHub connectors had never ingested repo *documentation* before
this, only PRs/commits/reviews/messages. Decision docs (`docs/adr/`,
`docs/decisions/`, `adr/`, `decisions/`) are now a fifth ingested
`source_type`, correlated using the exact same pipeline Slack/Jira
correlation already has — see [ADR 0027](../adr/0027-decision-debt.md)
for the full reasoning, including why ingestion (not a live per-request
fetch) and why extending `engine.correlation` (not a new heuristic) were
both deliberate choices, not the path of least resistance.

## Found live, not just in review

- **The original three-candidate pitch for this feature was checked
  against the real ingested-data shape before committing to the "full"
  version, the same discipline that shaped PR Blast Radius (3.7) and
  cut Drift Finder before it.** The cheaper alternative on the table —
  flag PRs by discussion-to-diff-size ratio alone, no new ingestion —
  was explicitly rejected in favor of building real decision-doc
  ingestion, specifically because a discussion-volume proxy can't
  actually tell "documented" from "undocumented," only "discussed a
  lot," which is a materially weaker claim.
- **A post-ship question ("is PR the only entry point?") surfaced a real,
  worth-naming scope boundary rather than a bug.** `scan()` only ever
  flags `source_type == "pull_request"` — commits are consulted only as
  a signal (author activity), never as a flaggable unit themselves. A
  repo that commits directly to `main` without PR review is invisible to
  this feature entirely. Considered extending to raw commits directly
  afterward and deliberately did not: scanning every commit the same way
  as every PR would mostly *duplicate* PR-level flags (several commits
  routinely share one PR's ticket key) rather than add coverage, plus a
  real ~5x cost increase in correlation calls per scan (100 commits vs.
  ~20 PRs per repo, per the existing `_COMMIT_LIMIT_PER_REPO` cap). A
  narrower, ticket-key-grouped version (flag a ticket key only when it
  appears in commits but in zero ingested PRs) would avoid the
  duplication problem, but needs real new aggregation logic, not a copy
  of the existing PR loop — scoped, costed, and deliberately not built
  this round; see "Open items" below.

## Open items carried forward

- **PR-only scope, by choice, not oversight** (see above) — worth
  revisiting specifically for a trunk-based/no-PR-review repo, not a
  general "more coverage" upgrade.
- The fixed decision-doc folder allowlist (`docs/adr`, `docs/decisions`,
  `adr`, `decisions`) has no per-repo override — a repo with a different
  layout entirely won't have its decision docs found. Same tradeoff
  `_TICKET_KEY_PATTERN` already makes elsewhere: covers the common case
  honestly, not a general solution.
